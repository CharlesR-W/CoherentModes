Every command that produced the data on this site, in the order they must run, with the files each one writes and its approximate Modal cost. Commands run from explore/cifar_coherent/ in the repo unless a block says otherwise. The last section rebuilds the site from data that already exist; everything before it regenerates that data.

What you need

  • uv on the path. Every command below names its own dependencies with uv run --with ....
  • A Modal account for any stage marked Modal. The measurement files are not in git: they live on the Modal volume cm-cifar-coherent (public files under /analysis/<tag>/, scratch under /work/<tag>/, checkpoints under /runs/<run>/), and each study's fetch command copies the public files into data/<tag>/. CIFAR-10 is read from the read-only volume crw-modelzoo-train.
  • The ModelZoo source at ~/code/ModelZoo: the training and measurement images copy ~/code/ModelZoo/src into the container.
  • Scratch off a small /tmp: export TMPDIR=/var/tmp/cm-pipeline; mkdir -p "$TMPDIR".
  • Detached launches. Every Modal launch spawns a coordinator that survives the local session and writes its call id to runs/. Wait until the matching status command prints a result (not running) before starting the next stage: later stages read earlier stages' files from the volume.
  • Licence. seba.py and test_seba.py are ports of the authors' reference implementation (gfroyland/SEBA) and are licensed GPL-3.0-or-later accordingly.

The data tags: r20s0 legacy measurement of ResNet-20 seed 0 (layouts and probe only are still used); r20s0b the schema_v2 measurement every chart is built from; r20s1b layouts of seed 1; r20s0d the dot (Euclidean) kernel variant; data/kernels/ the gradient-side kernel comparisons; r20s0c the baselines study; ../spectral_align/data the alignment study.

Local tests

CPU only, each in seconds. Each prints a final line ending in passed.

export TMPDIR=/var/tmp/cm-pipeline; mkdir -p "$TMPDIR"
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
uv run --with torch --with numpy python test_seba.py                    # SEBA against the reference implementation
uv run --with torch --with numpy python test_coherent.py                # planted three-group check of the construction
uv run --with torch --with numpy python test_product.py                 # product (composition) blocks
python3 test_provenance.py                                              # stale cache records cannot be reused
uv run --with torch --with numpy python test_dot.py                     # dot-kernel identities (SPEC_DOT.md section 1)
uv run --with torch --with numpy --with scipy python test_coarse.py     # coarse-graining identities and bounds
uv run --with torch --with numpy --with scipy python test_markov.py     # Markov-closure measures
uv run --with modal --with torch --with numpy python test_kernels.py    # GGN / NTK Gram estimands (imports kernels_modal.py)
# the full schema-v2 path on a synthetic fixture (not evidence about any network):
uv run --with torch --with numpy python schema_v2.py fixture data/_fixture
uv run --with torch --with numpy python schema_v2.py validate data/_fixture

Training (Modal, modal_train.py)

ModelZoo's resnet20/relu-seed<s> recipe re-run on an L40S with ModelZoo's own training loop (a re-run on a different GPU, not a bit-identical copy of the zoo run). App cm-cifar-coherent-train.

uv run --with modal python modal_train.py deploy
uv run --with modal python modal_train.py launch              # seed 0
uv run --with modal python modal_train.py launch --seed 1     # seed 1 (layouts only)
uv run --with modal python modal_train.py status <launch-id>  # launch id printed by launch, also in runs/

Writes (volume): /runs/resnet20-relu-seed0/ and /runs/resnet20-relu-seed1/ (checkpoints/step_<step>.pt and manifest.json, the training curve).

Legacy measurement (Modal, measure.py, tag r20s0)

Must run before the schema_v2 stages: measure_v2.py launch all copies its probe and the layouts of seed 0. App cm-cifar-coherent-measure.

uv run --with modal python measure.py deploy
uv run --with modal python measure.py launch resnet20-relu-seed0 r20s0 0,64,256,1024,2560,6400,25600,64000
uv run --with modal python measure.py status r20s0
uv run --with modal python measure.py fetch r20s0

Writes data/r20s0/: probe.npz (the {{fact:n_images}} probe images, indices and labels), umap_<step>.npy (layouts of seed 0), stats_<step>.json, kappa.json, spec_<step>.npz (legacy operator; not used by the site).

The main measurement (Modal, measure_v2.py, tags r20s0b, r20s1b)

App cm-cifar-coherent-v2. The stage all runs extract, spectra, comparisons and decod in turn; each can also be launched alone. The third argument is the tag (default r20s0b).

uv run --with modal python measure_v2.py deploy
uv run --with modal python measure_v2.py launch all            # wait: measure_v2.py status all
uv run --with modal python measure_v2.py launch derivatives    # wait: measure_v2.py status derivatives
uv run --with modal python measure_v2.py launch validate       # wait: measure_v2.py status validate
uv run --with modal python measure_v2.py launch sweep          # 19 candidate rules x 15 snapshots
uv run --with modal python measure_v2.py launch prodspectra    # product (composition) blocks
uv run --with modal python measure_v2.py launch specembed      # spectral layout (diffusion coordinates)
uv run --with modal python measure_v2.py launch layouts        # seed 1, after its training has completed
uv run --with modal python measure_v2.py launch audit          # cache provenance audit (runs/provenance-final.json)
uv run --with modal python measure_v2.py fetch r20s0b
uv run --with modal python measure_v2.py fetch r20s1b
uv run --with torch --with numpy python schema_v2.py validate data/r20s0b

Writes data/r20s0b/ (file by file in the table below) and data/r20s1b/ (umap_<step>.npy, meta.json). Scratch on the volume under /work/r20s0b/ includes the operators operators_<step>_<site>.npy and the centred Grams gram_<step>_<site>.npy that the coarse-graining, baselines and kernel stages read.

Coarse-graining and Markov closure (Modal, coarse_modal.py)

Specification in SPEC_COARSE.md. App cm-cifar-coherent-coarse. Reads the r20s0b operators on the volume, so it runs after measure_v2.py launch all. One unit is one (checkpoint, rule); pilot runs the unit at step {{fact:final_step}} with kernel rule {{fact:mode_name.rule0}} and launch the others. The Markov stage reads the coarse files, so it runs after the coarse launch has completed.

uv run --with modal python coarse_modal.py deploy
uv run --with modal python coarse_modal.py pilot
uv run --with modal python coarse_modal.py status pilot
uv run --with modal python coarse_modal.py launch
uv run --with modal python coarse_modal.py status              # the launch
uv run --with modal python coarse_modal.py fetch               # -> data/r20s0b/coarse/
uv run --with modal python coarse_modal.py markov-pilot
uv run --with modal python coarse_modal.py markov-launch
uv run --with modal python coarse_modal.py status markov-launch  # the Markov launch
uv run --with modal python coarse_modal.py fetch-markov        # -> data/r20s0b/coarse/markov_*.npz
uv run --with numpy python coarse_summary.py                   # first: rewrites coarse_facts.json
uv run --with numpy python markov_summary.py                   # second: merges its facts into coarse_facts.json

The last command of the check prints the coordinator's result when it has finished and raises TimeoutError while it is still running. The two summaries must run in this order: coarse_summary.py rewrites coarse_facts.json and markov_summary.py adds the mk.* facts to it.

Dot kernel and gradient-side kernels (Modal, measure_v2.py tag r20s0d, kernels_modal.py)

Specification in SPEC_DOT.md. The tag r20s0d selects the dot kernel inside measure_v2.py (construction.KERNEL_OF_TAG). Its extract copies the kernel-independent files (probe, curves, decodability, per-image points, gradient Grams) from r20s0b, so r20s0b's all and derivatives stages must have completed. No decodability or derivative stage runs for r20s0d; its layouts stage makes dot-PC layouts of seed 0 (no seed 1).

uv run --with modal python measure_v2.py launch extract r20s0d       # wait: measure_v2.py status extract r20s0d
uv run --with modal python measure_v2.py launch spectra r20s0d
uv run --with modal python measure_v2.py launch comparisons r20s0d
uv run --with modal python measure_v2.py launch prodspectra r20s0d
uv run --with modal python measure_v2.py launch specembed r20s0d
uv run --with modal python measure_v2.py launch layouts r20s0d
uv run --with modal python measure_v2.py launch validate r20s0d
uv run --with modal python measure_v2.py fetch r20s0d

Gradient-side Grams (GGN, trace NTK, loss-gradient cosine) and the cosine / dot comparisons: app cm-cifar-coherent-kernels. The optional last argument of launch is the stage's budget in USD; a stage refuses to fan out if its projection from the pilot exceeds it. Each pilot must finish before its stage, which reads the pilot's timing record. Launch records accumulate in runs/kernels-modal.json.

uv run --with modal python kernels_modal.py deploy
uv run --with modal python kernels_modal.py launch pilot             # wait: kernels_modal.py status pilot
uv run --with modal python kernels_modal.py launch kernels 1         # wait: kernels_modal.py status kernels
uv run --with modal python kernels_modal.py launch analysis-pilot    # wait: kernels_modal.py status analysis-pilot
uv run --with modal python kernels_modal.py launch analysis 3        # wait: kernels_modal.py status analysis
uv run --with modal python kernels_modal.py fetch                    # -> data/kernels/compare_{single,blocks,ggn}.json

Baselines study data (explore/cifar_baselines/, tag r20s0c)

Stored by the baselines study (schema in SCHEMA.md): the sources' labels and their agreement rows on every explorer block, the null draws, stability, linear content and ablations of the representative blocks, the random-subspace SEBA runs, the planted-benchmark summaries (NOTES_B.md) and the transfer pilot (TRANSFER.md). Computed by the site build (site/baselines.py) with the study's own functions: the predicted-class agreement rows, the agreement of the stored null draws with the method, the source-by-source matrices and the snapshot-by-snapshot set agreement ({{fact:bn.n_perm_site}} permutations each, cached in ~/.cache/cm-site-bn/). The added data take {{fact:bn.site_mb}} MB.

From explore/cifar_baselines/. measure_b.py reads the r20s0b Grams, operators and block files on the volume. Its launch takes a hard cap and a pause threshold in USD; the followup stage takes its own cap. Run-by-run notes: NOTES_A.md (measurement), NOTES_B.md (planted benchmarks), NOTES_C.md (transfer pilot).

cd explore/cifar_baselines
uv run --with modal --with pytest --with torch --with numpy --with scipy --with scikit-learn --with deeptime \
    pytest -q test_stats.py test_sources.py test_nulls.py test_measure_b.py test_planted.py test_transfer.py
uv run --with modal python measure_b.py deploy
uv run --with modal python measure_b.py launch all 8 6        # wait: measure_b.py status all
uv run --with modal python measure_b.py launch followup 2     # wait: measure_b.py status followup
uv run --with modal python measure_b.py fetch                 # -> ../cifar_coherent/data/r20s0c/
uv run --with modal --with numpy python measure_b.py validate              # checks data/r20s0c against SCHEMA.md
# planted / null benchmarks (CPU fan-out, volume cm-cifar-baselines-bench)
uv run --with modal python bench_modal.py deploy
uv run --with modal python bench_modal.py launch full         # prints a run id
uv run --with modal python bench_modal.py fetch <run_id>     # -> out/bench/parts/<run_id>/
uv run --with numpy --with torch python bench.py summarise out/bench/parts/<run_id>   # -> out/bench/summary.json
# transfer-operator pilot (volume crw-cm-transfer-results)
uv run --with modal --with numpy --with scipy python transfer_modal.py deploy
uv run --with modal --with numpy --with scipy python transfer_modal.py launch-real
uv run --with modal --with numpy --with scipy python transfer_modal.py fetch <run_id>   # -> out/transfer/real/

NOTES_B.md records a partition rerun of some benchmarks after the full sweep; repeat it as described there before summarising.

Alignment study data (explore/spectral_align/)

Protocol in SPEC.md there; ResNet-32 and ResNet-56 are trained with the ResNet-20 recipe and only the number of blocks per stage changed (nets.py). From explore/spectral_align/:

cd explore/spectral_align
uv run --with torch --with numpy --with dtw-python --with pytest pytest test_align.py -q
uv run --with modal python train_modal.py deploy
uv run --with modal python train_modal.py launch 32 0          # likewise 32 1, 56 0, 56 1; status: train_modal.py status
uv run --with modal python measure_modal.py deploy
uv run --with modal python measure_modal.py launch pilot
# inspect the cost gate it prints; redeploy with SALIGN_TIMEOUT set to its suggested_timeout
uv run --with modal python measure_modal.py launch all
uv run --with modal python measure_modal.py status
uv run --with modal python measure_modal.py fetch              # -> data/
uv run --with numpy python -I sanity.py                        # tensors and probe indices / labels
uv run --with numpy --with scipy --with dtw-python \
    --with torch --index https://download.pytorch.org/whl/cpu --index-strategy unsafe-best-match \
    python analyze.py data                                     # -> analysis/data/ (read by the site build)

The site build (site/alignment.py) reruns nothing: when analysis/data/ is older than the data directory it stops and prints the analyze.py command above. Data used by this build: {{fact:al.data_note}} Data shipped to the page: of the all-pairs distance tensors, only the blocks the figures draw (each network's site × site matrices at each checkpoint, each site's checkpoint × checkpoint matrix, and the site × site matrices of every pair of networks at each checkpoint and at iso-accuracy), stored as uint16, fetched per distance; the eigenfunctions are fetched per snapshot. {{fact:al.site_mb}} MB in all, of which {{fact:al.site_vectors_mb}} MB are eigenfunctions. Probe images: {{fact:al.probe_match}}.

Experiment generators

Each experiment in the Experiments tab has a generator site/experiments/<id>.py that reads data/r20s0b/ (and the other local data above) and writes only site/assets/x/<id>.json, site/assets/x/<id>.facts.json and site/assets/fig/x_<id>_*.png; the appendix generators app_choices.py (Appendix A) and app_measurements.py (Appendix D) write site/assets/x/app-choices.* and site/assets/x/app-measurements.*. The ids are listed in site/content/experiments/index.json. check_fragment.py validates each experiment's fragment, and with --appendix each appendix, without building, against the non-experiment facts of the last full build (site/build_inputs/facts_base.json if present, else viewer/site/d/facts.json).

for id in $(python3 -c 'import json; print(" ".join(e["id"] for e in json.load(open("site/content/experiments/index.json"))))'); do
  uv run --with numpy --with scipy --with matplotlib python -I site/experiments/$id.py r20s0b || break
  python3 site/check_fragment.py $id || break
done
for app in app_choices app_measurements; do
  uv run --with numpy --with scipy --with matplotlib python -I site/experiments/$app.py r20s0b || break
done
for app in choices baselines method-details measurements reproduce; do
  python3 site/check_fragment.py --appendix $app || break
done

Release build

Needs every local data directory above: data/r20s0b, data/r20s1b, data/r20s0c, data/r20s0d, data/kernels, ../spectral_align/data (with its analysis/data/) and site/assets/questions.json. --release fails on a missing experiment fragment, an unknown fact, a missing data-src target or image, or missing alignment data; without it the build writes placeholders instead.

uv run --with numpy --with pillow --with scipy --with scikit-learn python site/build_site.py r20s0b \
    --layout-tag r20s1b --baselines r20s0c --alignment ../spectral_align/data --dot-tag r20s0d --clean --release
python3 site/check_browser.py --session release-check                   # renders every live figure, checks aliases
python3 -m http.server 8765 --bind 127.0.0.1 -d viewer/site             # then open http://127.0.0.1:8765/

Output: viewer/site/ (the deploy root, with .nojekyll; its fact table is viewer/site/d/facts.json). To publish, copy viewer/site/ into an empty directory, commit it as a single orphan commit on the branch gh-pages and force-push; that branch holds only the built site.
