Definitions, the choices I made, what could go wrong and how it was checked, and how to rebuild the page. The construction is the Pythia study's, unchanged; what is new is the recurrent state and its two views, listed under deviations.

Model, probe and cells

Model. {{fact:model_full}} at revision {{fact:revision}}: Mamba-1, {{fact:n_layers}} blocks on the residual stream, width {{fact:d_model}}, inner width {{fact:d_inner}}, SSM state size {{fact:d_state}}, conv kernel {{fact:conv_kernel}}, RMSNorm, residual kept in float32, trained on the Pile (about 300B tokens) with the GPT-NeoX-20B tokenizer. It runs through Hugging Face's reference (torch) implementation of the scan; the fused mamba-ssm and causal-conv1d kernels are not installed. Checkpoints: the pinned trained weights, and MambaForCausalLM(config) after torch.manual_seed({{fact:init_seed}}) (HF's re-implementation of the reference init; no intermediate training checkpoints are published). Transformers {{fact:transformers}}, torch {{fact:torch}}.

Probe. The Pythia study's {{fact:n_items}} snippets, copied verbatim: {{fact:n_per_source}} per source, 128 tokens after an end-of-text token, de-duplicated without labels and shuffled. Both models share the tokenizer backend, so item $i$ is the same token sequence in both studies; the check is described under deviations.

Cells and the state. The model reads each snippet one token at a time with HF's cache, batched over snippets. After each step, a forward hook gives the residual after block $l$ (before the final norm at L24), and the cache gives every layer's conv buffer and SSM state. The conv buffer kept is the last three columns of HF's four-column buffer: the next step discards the oldest column, so only those three are carried forward. Positions 0 to 3 are left out as in the Pythia study.

Every vector goes through the same standard step: centre over the $N$ snippets, scale each row to unit length, take cosines, in float64. For the state and stack views each constituent goes through that step on its own, the cosine matrices are averaged with equal weight, and the average is double-centred and renormalised, as the Pythia slab was. This equals the cosine matrix of the concatenated normalised constituents scaled by $1/\sqrt{\#\text{constituents}}$ [thm] (checked in P3). The equal weighting is a choice (D-M1): the conv inputs and the accumulated SSM products have unrelated scales, and raw concatenation would let the parameterisation decide.

Glossary

item, snippet
One of the {{fact:n_items}} probe texts (a site in the theory's language).
cell
A (checkpoint, layer, position, view); its walk $P_c$ is built from that view.
recurrent state, constituent
Layer $m$'s conv buffer $c^m_t$ and SSM state $z^m_t$ after $t$ tokens; each is one constituent of the state and stack views. The whole state $\Sigma_t$ is all {{fact:n_layers}} layers' pairs.
block
A run of cells along one axis, with equal weights. Reading block: one layer, positions 4 to 128, trained, one view. Depth block: one position, layers L4 to L24, trained, point view. A single cell is also a block.
walk $P_c$, lazy walk $M_c$
$P_c$ is the Sinkhorn-scaled kernel of a cell (symmetric, rows sum to 1, zero diagonal); $M_c = \frac12(I + P_c)$.
block operator $\bar M$
The mean of the block's $M_c$. Its eigenpairs are $\lambda_k$, $\psi_k$ (with $\psi_0$ constant, $\lambda_0 = 1$).
retention $\rho_c$
$\rho_c(f) = f^\top M_c f / f^\top f$ in cell $c$; $\lambda_k$ is the mean of $\rho_c(\psi_k)$ over the block.
participation number PN
$(\sum_i \psi_i^2)^2 / \sum_i \psi_i^4$: about $N$ for a spread function, small for one sitting on a few items. Below 10 flags a localised mode.
coherent sets
The hard assignment from SEBA's $r$ sparse vectors on $\psi_0..\psi_{r-1}$; unassigned items are zero on all of them.
walk shares $T$, $W$
Equation (2) on the Overview with the grouping by the token at $t$ ($T$) or by source ($W$). Linear in $P$, so a block's value is the mean of its cells' values.
pair mixing ratio $X$
$X_c(A, B) = \frac{N-1}{|A||B|}\sum_{i \in A, j \in B} (P_c)_{ij}$: 1 for a walk that ignores sources.
span agreement $a_r$
Mean $\cos^2$ of the principal angles between the spans of $\psi_1..\psi_r$ of two cells, constant removed; null $r/(N-1)$.
matched Jaccard
Mean Jaccard index of two partitions' sets after the best one-to-one matching (Hungarian); null from {{fact:n_perm}} permutations, and a ceiling set by the set sizes.
own-source walk share
Per item and point cell, the share of its row of $P_c$ that lands on its own source (validation).
conductance $\phi$, clustering ratio $\Upsilon$
See the zoom.

The zoom, precisely

For a node with snippets $S$ and the block's averaged zero-diagonal walk $\bar P^S$ (rebuilt on $S$), the conductance of $A \subset S$ is $\phi(A) = \sum_{i \in A, j \notin A} \bar P^S_{ij} / \min(|A|, n - |A|)$. Because every cell's walk has the uniform stationary measure, the block's $\phi$ is exactly the mean of the cells' $\phi$ [thm]. Candidates are the level sets of $\psi_1$, $\psi_2$ and $\psi_3$; the cheapest with both sides at least $\max(16, \lceil 0.05 n \rceil)$ wins. With $\mu_k = 1 - \lambda_k(\bar P^S)$, the unconstrained $\psi_1$ sweep satisfies $\mu_1/2 \le h \le \phi_{\text{free}} \le \sqrt{2\mu_1}$ [thm], $h$ being the smallest conductance of any cut; the constrained $\phi^*$ satisfies only $\phi^* \ge h \ge \mu_1/2$. The clustering ratio $\Upsilon = \mu_2/\phi^*$ follows Peng, Sun and Zanetti (2015). For T4 the rebuild on $S$ restricts each constituent's raw inner-product matrix to $S$, double-centres it over $S$, normalises it to a cosine matrix, averages over constituents and then double-centres and renormalises, which is the stack view's own construction applied to the snippets in $S$; restricting the parent's averaged matrix is not the same thing and is not used.

Deviations

From the Pythia study (SPEC sections 1 to 8 of this study, and its README):

  1. The prefix slab is dropped; the state and stack views replace it (D-M4). The training axis is dropped; the HF initialisation is the one comparison checkpoint (D-M3).
  2. C1 splits in two. C1a compares recurrent decoding with the parallel forward pass; HF's Mamba casts parts of the computation to float32 even after .double(), so C1a is a mixed-precision check at 1e-4, not Pythia's float64 gate at 1e-10. C1b, the exact identity, resumes the decode at $t = 64$ from the stored state alone (column 0 of the rebuilt conv buffer is set to NaN, so any read of it would poison the result) and compares with the original decode.
  3. The decode is fed cache_position = max($u$, 3) rather than $u$: HF's decode branch writes the new conv input at that index clamped to 0..3, so the true index below 3 would put it in the wrong column. Every value from 3 on is equivalent.
  4. The probe check is reformulated: the literal check (re-encoding each stored text gives the stored ids) fails on 16 items under Pythia's own tokenizer too, because a snippet can end inside a merge. What is asserted instead: identical tokenizer backends, every id below the vocabulary size, exact decoding of every text, and the same 16 re-encoding failures under both tokenizers.
  5. The cross-architecture comparison goes in its own file, cross_arch.json, made locally after the run.
  6. Layouts: AlignedUMAP for the point grid, and separately for the state and stack grids (the explorer's view switch); the strip is the point view across the two checkpoints.

How to reproduce

The pipeline (explore/mamba_coherent/) runs on Modal: a probe unit, one GPU unit per checkpoint for the recurrent decode, the states and the cosine matrices, one CPU unit per checkpoint for kernels, walks, blocks, statistics, and a final unit for trees, layouts and validation. The cross-architecture comparison and the page are then built on the orchestration machine:

export TMPDIR=/var/tmp/cm-mb
cd explore/mamba_coherent
uv run --with torch --with numpy --with scipy python -I cross_arch.py ../lm_coherent/data/p160t data/{{fact:tag}}
uv run --with numpy --with matplotlib --with pillow python -I page/build_page.py {{fact:tag}}
bash page/verify.sh /var/tmp/cm-mb/shots

Construction fingerprint {{fact:fingerprint}}; data tag {{fact:tag}}; Modal spend {{fact:run.cost}}. Run ids and the spend table are in explore/mamba_coherent/README.md.
